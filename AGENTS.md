# Правила работы над калькулятором ВСЗ

## До изменений

1. Проверь актуальный `main` на GitHub, зафиксируй его HEAD SHA. Проверь открытые PR, состояние рабочей ветки и отчёт предыдущей итерации.
2. Прочитай [README](README.md), [STATUS](docs/STATUS.md), [ROADMAP](docs/ROADMAP.md), документы и инструкции затронутой области.
3. Работай в отдельной ветке. При продолжении итерации используй её существующую ветку и Draft PR. Прямые изменения в `main`, force push и удаление чужих изменений запрещены.

## Инженерные расчёты

- Изменение утверждённой формулы требует обоснования, проверки по методике и контрольным данным. Не подгоняй расчёт под примерное или округлённое значение.
- Указывай единицы при вводе, преобразовании и выводе. Различай миллиметры и микрометры. Сохраняй направление подхода и знак измеренного отклонения. Обосновывай и документируй любое их преобразование.
- Подтверждай вычислительные результаты автоматическими тестами по независимым контрольным данным. Указывай точность сравнения и основание для неё.
- Отдельно фиксируй проверку программных вычислений и сведения о достоверности исходных измерений. Успех тестов сам по себе не подтверждает условия испытания станка.

## Документация и передача результата

- PRO отвечает за методику и независимый аудит, Chat Astra — за требования и архитектуру. Утверждённые результаты аналитических подэтапов переносит в GitHub только Work.
- После каждого этапа обнови [STATUS](docs/STATUS.md), сверь статус с [ROADMAP](docs/ROADMAP.md) и сохрани отчёт в [docs/iterations](docs/iterations/README.md). Укажи исходный HEAD, коммиты, ссылку на PR, фактические проверки и открытые вопросы. Отметь частичный результат, если осталась невыполненная работа.
- Перед коммитом проверь список файлов в индексе и их полный diff. Не добавляй секреты. Храни исходный PDF стандарта, книгу Excel с заводскими измерениями и необработанные стенограммы вне публичного репозитория. Для публикации других внутренних материалов требуется отдельное разрешение. Правила `.gitignore` дополняют проверку содержимого.
- Создай коммит, опубликуй рабочую ветку и открой или обнови Draft PR в `main`. Подтверди на GitHub состояние PR и его HEAD. Отмечай этап завершённым только после проверки его критерия готовности. Для слияния требуется разрешение пользователя.
