# ADR-0002 — проект численной политики PRE-06

**Proposed — ожидает согласования.** Порядок вычислений и проверки ниже относится к проекту `vsz-num-0.2`. Сведения об испытании, пригодности прибора и приёмке станка рассматриваются отдельно. [Текст §§9.2 и 9.4](../methodology/math-spec.md), [фактические проверки Work](../validation/pre06-numerical-policy-verification.md).

## Основание

Прежний порядок теряет локальный разброс на P02, а раннее локальное центрирование 03А также теряет разности средних, ширину полос и точную компенсацию. Измерительный источник и его двоичное представление могут дать разные характеристики до начала вычислений. Поэтому у двух слоёв проверки разные критерии.

## Решения к согласованию

| Вопрос | Предложение PRO | Ответственный и статус |
| --- | --- | --- |
| Метод s | Один метод sample-n-minus-1 на испытание, пять повторов и делитель 4. Для размаха нужны отдельные ID и ожидания. | Требует утверждения метрологом, Q9/D13. |
| Численная архитектура | Вход и выход binary64, рабочие суммы и дисперсии точные рациональные, корневые выражения с сертификатами. | Требует решения владельца. |
| Влияние d→b | Отдельные бюджеты Aᵧ в единицах поля и безразмерные ρᵧ по семействам. Величины в мкм² имеют свой бюджет. | Метролог и владелец согласуют численные значения и область применения. |
| Критерий вычислений | Биты каждого поля равны RN64 независимого значения над теми же b. Проверяются и точные отношения. | Требует подтверждения владельцем и независимой проверки 06. |
| Выходной диапазон | Точный ноль либо конечный нормальный RN64 для каждого обязательного поля. Ненулевой subnormal, потеря ненулевого выхода в ноль и overflow блокируют успех. | Требует согласования. |
| Дисперсия | Обязательное самостоятельное поле для каждой серии, округляется из точной выборочной v. | Требует подтверждения. |
| Диагностика | PRECISION_LOSS с причиной, стадией, адресом, действием и ключом попытки. При failed закрыты все успешные числовые секции. | Проект контракта уточнён, реакции подлежат проверке в 06. |
| Округление | Для вывода отдельно округлять точный объект binary64 к точному десятичному шагу с ties-to-even. Точный ноль результата +0, знак исходной строки сохранён. | Требует согласования шага, правила и версии форматтера. |
| Версия политики | vsz-num-0.2 идентифицирует рассмотренное предложение. | Proposed. Фактическое имя и содержание утверждает владелец. |
| Предел ресурсов | Адаптивное уточнение 128, 256, 512, 1024 значащих бита как кандидат. Неудостоверенное отношение или поле в пределах ресурса даёт явный отказ. | Требует проверки и решения о рабочих лимитах. Отдельные опыты с 10 000 позициями не устанавливают максимум. |

## Версии и воспроизведение

| Объект | Что идентифицирует |
| --- | --- |
| Профиль и его версия | Область процедуры и правила входного набора. Идентификатор текущих эталонов — `gost-27843-2006-linear-axis-le-2000-v1`. |
| Редакция математической спецификации | Документ 0.2 PRE-06, основанный на 0.1. Формулы §§3–6 прослеживаются до исходной версии. |
| Численная политика | Границы d→b, бюджеты, числовые поля, обязательные сертификаты, диапазон и отказы. |
| Метод s | Отдельное поле sdMethod и статус его утверждения. |
| Формат данных | Версия переносимого файла vsz-trial 1.0. У синтетических фикстур собственная схема vsz-fixtures-1.0. |
| Реализация и показ | algorithmVersion идентифицирует исполняемый вычислитель, numericalPolicyVersion — его правила. Форматтер имеет отдельную версию, шаг и единицу показа. |

Новая версия политики требуется при изменении представления входа, фиксированных бюджетов, вычислительного результата или его канонизации, предикатов равенства, допустимых выходов и лимитов, влияющих на успех либо отказ. Эквивалентная оптимизация с тем же контрактом получает новую версию реализации. Изменение только оформления относится к версии форматтера. Ключ попытки и исходный снимок определены в [модели испытания](../architecture/data-model.md).

Настройка бюджета на отдельное испытание пока не согласована. При её принятии в будущем понадобится включить её в хешируемые inputs, менять inputRevision и признавать прежний расчёт устаревшим при правке.

## Условие пересмотра

Если согласованные бюджеты источника недостижимы при d→b, отдельно рассмотреть вычислительный профиль от точных десятичных d. До решения по этому профилю потери преобразования видны инженеру. Для допуска 07 нужны утверждение метода, политики и ресурсов и принятый владельцем независимый результат 06.
