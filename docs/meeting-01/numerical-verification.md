# MEETING-01Б. Контроль справочного примера А.1

**Результат.** Для 11 позиций и 110 напечатанных отклонений проверены все 12 характеристик. Действующее ядро вернуло ровно те биты, которые сертифицировал независимый Python для представленных входов. Размах M по исходным десятичным данным равен **3,99 мкм**. Восьми характеристикам соответствует обычное конечное округление на точность осевой сводки. Для A↓, R, R↑ и R↓ остаётся воспроизводимое расхождение с печатью.

2. Присвоить печатным позициям 1…11 локальные ID p01…p11. Прочитать все координаты из строки $P_i$ как десятичные строки в мм, от 6,711 до 1750,920. В каждой паре столбцов **слева ↓, справа ↑**. В каждой строке $j=1,\ldots,5$ перенести отклонение со знаком в адрес (ID, направление, повтор), единица мкм. Координату из отклонения повторно не вычитать. Проверены все 11 координат, 22 заголовка направлений и 110 значений по независимой раскладке справочного листа XLSX. Паспортную длину из разности крайних координат не выводили.
3. Для слоя $d$ прочитать строки как точные дроби. В [контуре этапа 06](../../tests/verification/iteration-06/verify_reference.py) передать по 5 дробей каждого направления в `exact_position`, затем словарь по ID в `axis_reference`. Использован выборочный $s$ с делителем 4. Дисперсии проверены также через попарные разности. Выбор экстремумов и равенства выполняется до округления.
4. Для слоя $b$ передать ту же транскрипцию через `position_reference` и [проверяющий адаптер](../../tests/core/axis_oracle.py). Каждый десятичный вход преобразуется в binary64, затем его машинное значение рассматривается как точная дробь. [Сертификат](../../tests/verification/iteration-06/rounding.py) проверяет принадлежность точного результата ячейке округления к ближайшему binary64 с выбором чётного при равенстве. Ответы TS в построении ожиданий не использовали.
5. Те же исходные строки отдельно передать в [calculateAxis](../../src/core/axis.ts) из проверяемой ветки, с экспериментальным профилем, `sourceUnit="um"` и неизвестным паспортным ходом. Получено `research-computed`. Сопоставлены 220/220 позиционных чисел (20 на позицию), 11/11 наборов активных ветвей повторяемости, 18/18 наборов источников экстремумов и 12/12 осевых битовых слов. Строки представления получены вызовом штатного [displayNumber](../../src/web/model.ts).
6. Для сравнения с печатью отдельно округлить **точное $d$** до ближайших 0,1 мкм, середину от нуля. Шаг осевой сводки 0,0001 мм соответствует 0,1 мкм. Для всех 165 локальных и 12 осевых значений принадлежность выбранному интервалу округления дополнительно проверена точным сравнением с его границами. Это диагностическая операция только для данного сравнения. Полный перенос А.1, машинные журналы и заводская книга использованы локально. Для повторения достаточно оригинала и перечисленных функций. Публичный пакет v1 сохранён в исходном виде.

## Почему M равно 3,99 мкм и что означает «24»

В позиции 3 направленные средние равны −0,34 ↑ и +3,42 ↓ мкм, их полусумма **+1,54**. В позиции 8 получены −4,28 ↑ и −0,62 ↓, полусумма **−2,45**. Это экстремумы среди всех 11 полусумм. Разность $1,54-(-2,45)=3,99$ мкм равна 0,00399 мм. В сводке А.1 строка M, столбец «Двустороннее», показывает 0,0040 мм. Изображённые в скобках уже округлённые экстремумы дают то же число на шаге печати.

В TS [позиция](../../src/core/position.ts) формирует `meanBoth`, затем [ось](../../src/core/aggregate.ts) берёт разность `mean_both_max` и `mean_both_min`. Независимый Python строит `mean_both` из дробей и выбирает его максимум и минимум по всем ID. Метод оценки s на M не влияет. Дополнительные синтетические контроли в штатных тестах дают M = 0 для T01–T03, 2,5 мкм для T04 и 2 мкм для T06. Синтетические контроли имеют собственные входы.

В справочном Excel **S24** содержит `MAX(C20:X20)-MIN(C20:X20)`, кэш 3,99 мкм и отображение 4,0 мкм. Число 24 достоверно встречается в адресе строки. Перевод между мм и мкм у А.1 числа 24 не даёт. В проверенных контекстах встречи источник устной цифры установить не удалось. Для проверки иной величины нужен конкретный лист, показатель или программа испытания. [Что было проверено по встрече](normative-audit.md).

## Контроль метода s и Excel

По альтернативной оценке п. 3.15 для пяти повторов $s=0,4299(\max x-\min x)$. В отдельном расчёте на тех же точных $d$ заменили только оценку рассеяния и пересчитали зависимые границы и повторяемости, затем вызвали прежний `axis_reference`. Получены, в мкм, A = 9,75548, A↑ = 6,08146, A↓ = 5,96352, R = 6,73734, R↑ = 3,26724, R↓ = 2,75136. Все E, M, B и B̄ сохраняются. Альтернатива не воспроизводит печатную сводку. Утверждение метода для завода остаётся у метролога.

В этой проверке прочитаны обе версии содержимого каждой ячейки XLSX — формула и сохранённое значение. Для каждого из двух листов найдены 209 формул, 22 вызова STDEV.S и ноль вызовов ROUND. Книга считает отклонения и выводит сводку в мкм. Формулы итогов по направлениям используют раздельные ряды, двусторонние — экстремумы, размахи или среднее по соответствующим позициям. Контроль кэшей проведён по всем 12 итогам на каждом листе; порог $10^{-12}$ мкм использован только для исторического сравнения с Excel.

- **EX-01, справочный лист.** K9 (позиция 5↓) содержит константу 1 вместо среднего 1,44 мкм. Занижение среднего направления ↓ на 0,44 мкм смещает знаковое среднее по 11 позициям на +0,04 мкм. В сводке отклоняется только S23 (B̄): −3,670909… вместо −3,710909… мкм. При одном знаке после запятой обе величины выглядят как −3,7. S24 от дефекта на этих данных не зависит.
- **EX-02, заводской лист.** Независимый расчёт подтвердил совпадение константы с текущим средним пяти повторов. Все 12 сохранённых итогов согласуются в указанном пороге. Разрыв зависимости при следующем изменении входа сохраняется. Заводские значения и реквизиты исключены из отчёта.
- Хеш оригинала до и после чтения совпал. Новый запуск Excel или Calc в части Б не выполнялся. Перерасчёт одноразовых копий табличным движком и разбор схем округления документированы в [исходном аудите Excel](../validation/excel-audit-summary.md).

**Классификация.** У А.1 установлен факт четырёх расхождений на заданных десятичных входах при обычном конечном округлении. Их нельзя отнести к формуле ядра, выбору двоичного представления или переводу единиц. Из исходных материалов не следует, какими были наблюдения до публикации и как готовились все печатные строки. Поэтому причина этих четырёх значений остаётся открытой. EX-01/02 — отдельные дефекты зависимости в исторической книге. Оснований для исправления математического ядра по проверенному примеру не обнаружено. [Передача в MEETING-02](meeting-02-handoff.md).
