# MEETING-02А. Матрица проверок

Результат полного запуска Vitest — **583/583** в восьми файлах. Из них 509 существующих тестов, 50 новых проверок геометрии и 24 новых проверки подготовки применения. Наблюдения и машинные параметры синтетические. Матрица связывает 14 сценариев [передачи MEETING-01](../meeting-01/meeting-02-handoff.md) с выполненными проверками.

| № | Сценарий | Фактически проверенный результат |
| ---: | --- | --- |
| 1 | Границы плотности | 500, 800, 1000, 1000,0001, 1200, 1500, 2000 мм дают 5, 5, 5, 6, 6, 8, 10. Дополнительные случаи по обе стороны 1200 отличаются в десятичном разряде, которого уже нет в binary64 |
| 2 | Паспорт и участок | При L = 1500 мм и участке 800 мм результат содержит обе длины, восемь позиций и семь соседних интервалов |
| 3 | Ход неизвестен, неверен или слишком велик | Пустота, пробелы, ноль, отрицательное число, неверная строка, длинная запись, 1e309 и 1e−500 приводят к адресным исходам. Запятая, точка и экспонента работают. 2000,0001 и 2000,00000000000000001 мм дают выход за профиль. Неподтверждённая длина оставляет рекомендацию неопределённой |
| 4 | План и полнота наблюдений | Пять новых позиций дают 50 различных пустых адресов с повторами 1–5 и прежними единицами. Внесённые по всем адресам значения сохраняются при изменении только условий |
| 5 | Равномерный шаг | Списки 0, 20, 40, 60, 80 и 1, 22, 43, 64, 85 получают нарушение для свободного выбора. У фиксированных позиций сохраняется основание. При неизвестном режиме отсутствует положительная оценка размещения |
| 6 | Дубли, машинные коллизии, порядок | Строки `1.0` и `1,00` совпадают точно. `1` и `1.00000000000000001` дают одну машинную координату. Повтор ID и обратный порядок имеют собственные коды. В каждом парном конфликте проверены оба адреса |
| 7 | Квантование | Из 10,001 и 10,002 мм получены две исходные строки и одна исполнительная координата 10 мм на сетке 0,01 мм. Проверены обе стороны середины шага относительно ненулевого начала, равномерность после приведения, смещение согласованной цели, повторная проверка границ, нулевой и отсутствующий параметры сетки |
| 8 | Координатная система и ресурсы | Отрицательные координаты допустимы. Проверены перевёрнутый участок, выход за механический предел, слишком крупная сетка, недостаток десятичных разрядов и превышение лимита m. Число позиций самопроизвольно не уменьшается |
| 9 | Подход и реверс | Левый и правый концы получают независимые результаты. Подтверждены состояния неизвестности, достаточной геометрии, недостатка пространства, противоречия объявленного отрезка механическому пределу и невозможного подхода. Достижение рабочей скорости остаётся инженерным условием |
| 10 | Воспроизводимость, ручная правка и отмена | Два вызова на независимых копиях дают одинаковые строки, интервалы, ID, версию и весь результат. Первое предложенное значение сохраняется после двух ручных изменений. Предпросмотр и отказ от подготовленного объекта не меняют исходник |
| 11 | Сохранность измерений | Проверены частичный и полный ввод, знаковый ноль, экспонента, единица mm, строки с запятой, незавершённый текст. Перенос измеренной цели, удаление и смена ID, включая сдвиг сеткой, возвращают `requires-preservation`. Наблюдения прежней цели не присваиваются соседней строке |
| 12 | Версии и гонки | Проверены конфликт trialId, редакции, digest, условий, ожидаемой версии, правка исходной и исполнительной строки. Повтор с квитанцией даёт `already-applied`. Действующая проверка актуальности ядра отклоняет старый успешный результат при переходе к новым входам |
| 13 | Условия и запись координаты | Новая версия условий меняет версию плана. При прежних inputs сохраняются редакция и digest, требуется пересмотр отчёта. Смена только написания координаты меняет арифметический ключ. Обратная правка возвращает прежний digest в более поздней редакции |
| 14 | Старая запись и T06 | В T06 сохранены ID, строки и наблюдения. При неизвестной прежней системе отсчёта перенос измерений заблокирован. Предварительный расчёт T06 при неизвестном паспортном ходе по-прежнему даёт 12 итогов, B = 4 и B̄ = 0,8 мкм |

## Воспроизведение

В корне репозитория последовательно выполнены `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, `npm run build:demo` и `npm run build -- --mode pages`. Все команды завершились успешно. Отдельный запуск `npx vitest run tests/planning` проверяет только новый модуль. Для полных тестов ядра нужны прежние зависимости Python, описанные в [пакете эталонов](../../tests/fixtures/v1/README.md).

Браузерное поведение предпросмотра, атомарная запись в React, возврат фокуса, обновление открытого отчёта и отображение ограничений на мобильных ширинах входят в MEETING-02Б. Здесь проверены возвращаемые данные, кандидаты на изменение и действие существующей проверки актуальности результата.
