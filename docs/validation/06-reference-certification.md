# 06-1. Независимая сертификация округления вычисленных полей

## 1. Назначение

Проверить предложенный контракт `bits(actual) == bits(RN64(reference))` для всех расчётных полей 32 положительных синтетических случаев v1. RN64 означает округление к ближайшему binary64 с выбором чётной мантиссы на середине. Для каждого поля проверяется конкретная пара «точное значение, наблюдавшиеся биты». Политика `vsz-num-0.2` имеет статус **Proposed**. [Математическая спецификация, §9.2 и §9.4](../methodology/math-spec.md) · [ADR-0002](../decisions/ADR-0002-numerical-policy.md).

## 3. Независимый математический метод

Эталон строится из наблюдений каждой серии. Средние и дисперсии — точные дроби. Значения со стандартным отклонением хранятся как рациональная часть плюс короткая сумма квадратных корней с рациональными коэффициентами. Для сравнения используются опубликованные предикаты 03А. Они объединяют корни, отношение подкоренных выражений которых является рациональным квадратом. После сокращения равенство рациональных частей проверяется точно. Для оставшейся разности корни ограничиваются снизу и сверху рациональными числами через целочисленный квадратный корень. Порядок признаётся установленным, когда весь интервал лежит по одну сторону нуля.

Rᵢ эталон получает как ширину интервала, охватывающего обе направленные полосы. Независимо проверяется точное равенство этой ширины максимуму трёх кандидатов. Сравнения внутренних выражений определяют и осевые экстремумы. При невозможности отделить значения в пределах 2 560 десятичных разрядов интервального предиката проверка сообщает об отсутствии сертификата.

Эталонный путь обходится публичным репозиторием. В дополнительном прогоне фактические поля дал проверенный скрипт кандидата PRE-06, SHA-256 `d256720939417bb91bf20770301128f295b2a2ad835329d44ba369e24670993b`. Кандидат предоставлял округлённые поля и проверял собственные источники. Ожидания строились отдельно. [Исследование PRE-06](pre06-numerical-policy-verification.md).

## 4. Десятичный эталон d и двоичный эталон b

Исходную десятичную строку читают как точную дробь. Пересчёт мм в мкм выполняется умножением на 1 000 до округления. Для каждого из 2 800 наблюдений проверяется ячейка округления при переходе d→binary64. Точное машинное b восстанавливается через `Fraction.from_float`. Публичный наблюдаемый путь получает полную десятичную запись этого b через `Decimal.from_float`.

Сохранённые ожидания v1 относятся к d. Адреса ожидаемых источников из v1 читаются для сопоставления уже после построения эталона над b. В `P02-offset-collapsed` представление сливает различные наблюдения. Его 112 вычисленных полей включены в проверку арифметики **над b**. Признак коллизии по проекту политики блокирует успешную выдачу результата испытания.

## 5. Сертификат RN64

Для наблюдаемого конечного числа y берутся оба машинных соседа. Границы ячейки — точные рациональные полусуммы y с каждым соседом. Слева и справа шаги могут различаться. Положение эталона относительно обеих границ и чётность младшего бита однозначно определяют совпадение. Математический ноль требует +0. Для ненулевого значения, округлившегося в ноль, дополнительно проверяется его знак.

За пределом наибольшего конечного числа для построения последней границы используется виртуальный сосед с модулем 2¹⁰²⁴. На пороге 2¹⁰²⁴ − 2⁹⁷⁰ округление даёт бесконечность соответствующего знака. Отдельные скалярные проверки покрывают нижнюю границу normal, subnormal, оба знака у нуля, нечётного и чётного соседа на половине, скомпенсированные корни на середине и иррациональные значения по обе стороны середины. Все 16 положительных граничных проверок прошли. Эти свидетельства характеризуют округление. Обработка отказа приложения проверяется отдельно.

## 7. Итоги оси

В каждом случае проверены **A, A↑, A↓, E, E↑, E↓, M, R, R↑, R↓, B, B̄**. A получена как разность общего верхнего максимума и общего нижнего минимума по обоим направлениям. Для M выбраны экстремумы двусторонних средних, для E — направленных средних. B̄ сохраняет знак. При агрегации используются точные позиционные выражения.

По оси удостоверены 32 × 12 = **384** поля. Совместно с позициями получено **5 984 независимых сертификата из 5 984** для каждого наблюдаемого пути. Среди них 867 точных нулей с битами +0 и 32 результата ровно на границе ячейки. Несовпадений, неразрешённых сравнений и пропущенных полей — 0.

## 9. Дисперсия

При пяти наблюдениях проверены два точных выражения — сумма квадратов отклонений от точного среднего, делённая на 4, и сумма квадратов десяти попарных разностей, делённая на 20. Совпали **560 из 560** пар. Для публичного поля v удостоверяется собственная ячейка округления. На T06 квадрат уже округлённого s равен 80,00000000000001 мкм². Такая подстановка отклонена.

## 10. Источники экстремумов и ничьи

Проверены 280 упорядоченных списков активных ветвей Rᵢ и 576 списков адресов осевых экстремумов (18 на случай). В 46 позициях несколько ветвей определяют Rᵢ, у 186 экстремумов несколько источников. Проверяется каждый ID, направление и порядок записи всех точных победителей.

При сопоставлении метаданных d и b изменения обнаружены в одном наборе, `P02-offset-collapsed`. Изменились списки ветвей во всех пяти позициях и списки источников `lower_min`, `upper_max`. Для остальных 31 набора списки совпали. Равенство отображаемых или независимо округлённых чисел само по себе не служит основанием включить адрес в список.

## 11. Отрицательные контрольные мутации

| Искажённый результат | Где и как обнаружен |
| --- | --- |
| Ноль вместо малого ненулевого s | В статическом `P02-mixed-scale`, p02 ↑, ожидаемые биты s — `3d719799812dea11`. Ноль вне ячейки. |
| Соседний машинный результат | R оси T06 сдвинута на один ULP вверх. Точное R лежит ниже левой границы ячейки подставленного числа. |
| Обратный знак B̄ | Для T04 вместо −4 мкм передано +4 мкм. |
| Другая ветвь Rᵢ | Для T06/p03 указан Cᵢ. Точный победитель — Rᵢ↑. |
| Потерян один источник максимума | В T01 из общего `upper_max` удалён один адрес при неизменном числе. |
| v из округлённого s | На T06/p03 ↑ передано 80,00000000000001 вместо 80 мкм². |
| Нечётный сосед на точной середине | Проверены скаляр с алгебраической компенсацией корней и реальная Bᵢ в M01/p00011. |
| Ошибки около нуля и overflow | Отвергнуты −0 для истинного нуля, +0 для отрицательной половины subnormal, преждевременная бесконечность и конечное число на точном пороге overflow. |

Отклонены все **12** намеренных подстановок. Дополнительно через весь цикл проверки в памяти переданы шесть числовых и две адресные ошибки. Получены шесть несовпадений, 279/280 верных списков ветвей, 575/576 верных списков экстремумов и общий отказ. Фикстуры на диске сохранили исходные байты.

## 12. Границы результата

Объём сертификации — опубликованные 32 положительных случая v1. Для 21 отрицательного случая воспроизведены исходные классы 03А. Массовые запуски PRE-06 на 227 352 полях, произвольные входы, полная выдача `failed/PRECISION_LOSS`, пределы ресурсов и ошибка d→b относительно допустимого бюджета остаются вне объёма этих 5 984 свидетельств. Метрологическое решение по s и решения по численной политике остаются открытыми.
