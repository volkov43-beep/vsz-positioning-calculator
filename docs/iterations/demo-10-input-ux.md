### Как читать состояния

Мятная подложка `#f3faf6` и граница `#729180` объединяют обязательные поля. Звёздочки на подписях расшифрованы компактной легендой. Для программного доступа у каждого обязательного поля задано `aria-required`. Красная граница и светло-красный фон сопровождают найденную ошибку ввода. По кнопке проверки доступны текст причины, значок предупреждения, адрес и переход в поле. Вычислительная диагностика выделяет адресованное поле или серию янтарной границей. Выбранная строка имеет боковую полосу у ID, фокус — синий контур. Инструкция различает мм и мкм, оба десятичных разделителя, знаки, ноль, пропуск и научную запись.

Разметка формы и адресные связи находятся в [Editor.tsx](../../src/web/Editor.tsx). [main.tsx](../../src/web/main.tsx) передаёт категорию существующей диагностики и выводит сообщение. Оформление находится в [style.css](../../src/web/style.css).

### Как форма считает измерения

Сначала дефект воспроизвели в Chrome на сборке 10А. В семи позициях шесть буквенных строк и две пятёрки дали «8 из 70 введено». На том же вводе в 10Б получены **2 корректных, 6 ошибок формата, 62 пустых** и отдельно **0 из 7 корректных координат**. После проверки список содержит 75 адресов (6 ошибок, 62 пустых измерения и 7 координат). [Снимок семи позиций](demo-10/counts.webp).

| Состояние | Пример и момент классификации | Учёт |
| --- | --- | --- |
| `empty` | Пустая строка или отсутствующее значение | Пропуск. После общей проверки поле помечается, его адрес попадает в список. |
| `editing` | Активная правка `-`, `0,`, `1e-` | Отдельный счётчик ввода. При выходе из поля или Enter запись проверяется в завершённом виде. |
| `valid-numeric` | `0`, `-0,0010`, `.5`, `-2.5E+3` | Увеличивает числитель своего счётчика. При завершении ввода `0,` допустимо по синтаксису ядра и сохраняется буквально. |
| `invalid-format` | Буквы, смешанный текст, повторный разделитель, одни пробелы, NaN, Infinity, незавершённая экспонента после выхода | Ошибка формата с объяснением и ссылкой на ячейку. |
| `numeric-rejected` | Слишком длинный источник, выход за предел экспоненты, ненулевое число, округляющееся в ноль, либо адресный отказ ядра для завершённого набора | Отдельный численный отказ. Отображаются причина и техническое обозначение. |

Счётчик наблюдений охватывает только десять отклонений в мкм на каждую позицию. Координаты в мм имеют отдельный числитель и знаменатель. Для каждой позиции селектор показывает количество пригодных наблюдений, состояние координаты и обнаруженные ошибки. Обязательность текстового обозначения оси проверяется отдельно. Полный ход и сведения об условиях остаются параметрами применимости процедуры и полноты отчёта.

### Адреса и граница с ядром

[Модель полей](../../src/web/inputValidation.ts) передаёт полную строку существующей функции `normalize`. Она применяет правила ядра для разделителей, знаков, экспонент, преобразования и ресурсных ограничений. Регулярное выражение интерфейса описывает только временные префиксы. Редактор хранит исходный текст. Проверка не записывает обратно машинное число. На смартфоне можно переключить цифровую клавиатуру на полную для ввода знака и экспоненты.

«Проверить» и «Рассчитать» проверяют завершённые записи. Пустота или ошибка формата останавливает действие перед вызовом проверки оси или расчёта. Раскрывающийся список содержит все локальные замечания. Переход выбирает позицию, прокручивает карточку или матрицу и фокусирует поле. Кнопка следующего замечания проходит по кругу: сначала непустые проблемные записи, затем отсутствующая ось и координаты, затем пустые измерения. Внутри группы сохраняется порядок позиций, направлений и повторов.

Для полного локального ввода используются прежние `checkAxisInputs` и `calculateAxis`. Коллизии значений обнаруживаются при проверке всего набора, вычислительные ограничения — на соответствующем этапе расчёта. Первая диагностика ядра сохраняет адрес и исходную причину. При отказе для дисперсии интерфейс адресует серию из пяти значений. Счётчики продолжают отражать индивидуальный ввод, даже если расчёт серии или всей оси остановлен.

На ширинах 390, 360, 320 px и при 320 px с корневым текстом 32 px (200%) карточка содержала координату в мм и два подписанных направления по пять повторов в мкм. Проверка из p07 вернула фокус в ошибочное поле p03 ↓ №4. Его подпись, значок и причина ошибки доступны без наведения. Проверены ввод минуса, точки, запятой, переключение `inputmode` с `decimal` на `text` и вставка экспоненты.

Для формы и результатов ширина документа совпала с шириной доступной области (375, 345, 305 и 305 px с учётом полосы прокрутки). На всех размерах присутствовали 12 показателей. В проверенных состояниях отсутствовали повторяющиеся ID и ссылки ARIA на отсутствующие элементы. Ошибочное наблюдение имело `aria-invalid="true"`, `aria-required="true"` и `aria-describedby` с ID собственной причины. Общий числовой счётчик не объявляет каждое нажатие клавиши.

Chrome работал с реальным DOM. Мобильные размеры воспроизведены в окне браузера. Физическая клавиатура Android/iOS, Firefox, Edge и озвучивание экранным диктором остаются непроверенными. При автоматическом проходе два быстрых перехода потребовали повторного нажатия. Переход к ошибке из уже открытой карточки затем воспроизведён на всех четырёх размерах. Полное соответствие WCAG не оценивалось.

### Производительность и независимая проверка арифметики

Один ввод в настольной матрице с преимущественно пустыми ячейками. В каждой серии 12 замен одного наблюдения. Время от отправки события input до завершения обновления DOM и синхронной раскладки, без ожидания отрисовки кадра. Приведены верхнее центральное значение выборки и максимум. Ввод обновляет модель и сводку полей. Вызов `calculateAxis` находится в обработчике запуска расчёта. При росте до 100 позиций задержка одного обновления возрастает. Из чистого рабочего дерева последовательно прошли `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, `npm run build:demo` и `npm run build -- --mode pages`. Ядро, синтетический T06, эталоны, решения по численной политике и документы методики совпадают с базовым main.
