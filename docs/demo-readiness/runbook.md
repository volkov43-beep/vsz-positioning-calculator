# Запуск демонстрационного калькулятора ВСЗ

Для встречи скачайте и распакуйте весь комплект в одну папку, например `C:\VSZ\DEMO-08`. Заранее установите Node.js 24 и Chrome. Готовый комплект работает с локального диска. Для него достаточно Node.js и браузера. Python и установка пакетов npm нужны только в описанных ниже сценариях разработки и проверки.

## За минуту до показа · PowerShell

Откройте PowerShell **в распакованной папке**, где видны `dist`, `scripts` и `docs`. Выполните:

```powershell
node --version
node .\scripts\serve-demo.mjs
```

Оставьте окно открытым. Введите в адресную строку Chrome **http://127.0.0.1:4173/**. Это локальный адрес ноутбука. Сервер отдаёт готовый однофайловый HTML из `dist` и слушает только петлевой интерфейс. Для остановки нажмите Ctrl+C в PowerShell. В автономном комплекте нет этапа скачивания зависимостей.

**Контроль запуска.** Нажмите «Загрузить пример T06» → «Рассчитать». Должны появиться B = 4 и B̄ = 0,8 мкм. [Чек-лист и восемь контрольных кадров](release-checklist.md) · [Текст выступления](director-demo-script.md).

Прямое открытие HTML двойным щелчком создаёт адрес `file://`. Этот режим не подтверждён. Для вычисления SHA-256 требуется доступный `crypto.subtle`. На испытанном локальном HTTP он доступен. Проверочный стенд — Linux x86_64, Chrome 156 (по User-Agent), Node.js 24.22.3 и npm 11.19.1. Отдельный прогон на Windows, Edge или Firefox предстоит выполнить на устройстве показа.

## Содержимое и проверка целостности

- `dist/index.html`, `dist/assets/`, `dist/axis.js`, `dist/position.js` — обычная статическая сборка. Сохраняйте структуру каталогов.
- `dist/VSZ-calculator-07D3.html` — отдельная сборка того же React-интерфейса и осевого ядра. Имя файла унаследовано из 07-Д3. Размер 281 213 байт. SHA-256: `ef89b63fde5419927be0791277f94db6a46a1b153c54404e9d5d00df13275963`.
- Контрольные суммы восьми файлов доступны в [манифесте](build-SHA256SUMS.txt). Ревизия исходников приложения — `e53fb68bcc89d8de75b059684b30923349f116ee`. Название комплекта DEMO-08В, версия npm-пакета 0.0.0, алгоритм axis-demo-1, профиль 1, численная политика vsz-num-0.2 (Proposed).
- `scripts/serve-demo.mjs` запускает один HTML. Папка `docs/demo-readiness` содержит инструкции, манифест и резервные кадры.

Сверка из корня распакованного комплекта или репозитория:

```powershell
Get-Content .\docs\demo-readiness\build-SHA256SUMS.txt | ForEach-Object {
    $hash, $path = $_ -split '\s+', 2
    if ((Get-FileHash -Algorithm SHA256 -LiteralPath $path -ErrorAction Stop).Hash -ne $hash) {
        throw "Контрольная сумма расходится: $path"
    }
    Write-Host "OK $path"
}
```

## Воспроизведение из исходников

Из корня репозитория с исходниками указанной ревизии (или итогового коммита DEMO-08В) выполните в PowerShell:

```powershell
npm.cmd ci
npm.cmd run typecheck
npm.cmd run build
npm.cmd run build:demo
```

Сначала создаётся статический каталог, затем добавляется самостоятельный HTML. Повторный `npm run build` очищает `dist`, поэтому однофайловую версию собирайте последней. Для проверки исходников тестами установите Python 3.12, затем выполните `python -m pip install -r tests/fixtures/v1/requirements.txt` и `npm.cmd test`. В проверочном окружении использовались Python 3.12.14 и mpmath 1.3.0.

| Режим | Команда из корня репозитория | Адрес |
| --- | --- | --- |
| Готовая статика Vite | `npm.cmd run preview -- --host 127.0.0.1 --port 4173 --strictPort` | http://127.0.0.1:4173/ |
| Один HTML на том же сервере Vite | Оставить предыдущую команду запущенной | http://127.0.0.1:4173/VSZ-calculator-07D3.html |
| Автономный комплект, без npm | `node .\scripts\serve-demo.mjs` | http://127.0.0.1:4173/ |
| Разработка с Vite | `npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort` | http://127.0.0.1:5173/ |

Запускайте только один сервер на порту 4173. Установку зависимостей из исходников выполните заранее при наличии интернета. Для проверки отдельной статической поставки тем же Vite можно запустить из подготовленного репозитория `npm.cmd run preview -- --outDir "C:\VSZ\DEMO-08\dist" --host 127.0.0.1 --port 4173 --strictPort`.

## Если показ прервался

| Ситуация | Как продолжить |
| --- | --- |
| Нет интернета или недоступен временный сайт | Открыть заранее распакованный комплект, выполнить команду автономного запуска выше, загрузить T06. |
| Вкладка закрыта, браузер перезапущен | Открыть локальный адрес заново. Введённые числа хранятся в памяти вкладки. Для возврата к исходному примеру снова загрузить T06. |
| Изменили чужую ячейку или получили ошибку ввода | Пока фокус в ячейке, Escape восстанавливает её исходную строку. Иначе выбрать «К полю ввода», исправить значение и пересчитать. Для полного сброса открыть «Начало» → «Загрузить пример T06» → «Подтвердить». |
| Отчёт сообщает об устаревшем результате | Выбрать «К измерениям» → «Пересчитать». Сверить номер редакции в отчёте. |
| Открыли file://, получен отказ Web Crypto или пустой экран | Запустить локальный сервер, ввести указанный HTTP-адрес в Chrome и повторить T06. При ошибке численной точности сверить исходную строку и восстановить пример. |
| node не найден, отсутствует HTML или порт занят | Заранее установить Node.js 24 и заново открыть PowerShell. Распаковать ZIP целиком. Освободить порт, остановив предыдущее окно своего сервера, либо в подготовленном проекте запустить Vite preview на порту 4174 и использовать адрес из консоли. |
| Сбой сохраняется | Открыть локальные WebP из чек-листа. Сказать зрителю, что это кадры проверенной репетиции. Возвращаться к живому показу после контрольного расчёта. |

## После разрешения на временный HTTPS-показ

GitHub Pages подходит для статического содержимого. Конфигурация Vite уже задаёт `base: "./"`. На стенде проверена загрузка по пути `/vsz-positioning-calculator/` и расчёт без прикладного API. Для пробного размещения отдельная правка исходников не требуется. [Устройство GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) · [Условия доступности Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/subtle).

1. Владелец подтверждает публичную аудиторию, ревизию, площадку, срок и ответственного за снятие копии. Для проекта Pages согласовать путь репозитория и временный адрес. Учитывать журналы запросов хостинга.
2. Для однократного размещения подготовить выделенный источник Pages только с обычной статикой из проверенного dist. Сверить SHA-256, публичное происхождение T06, видимость предупреждений. Заводские файлы, исходники, тесты и инструкции комплекта в сайт не включать.
3. После отдельного разрешения открыть фактический HTTPS-адрес и повторить чек-лист, сетевую проверку, отказ на пропуске и проверку Web Crypto. До этой проверки подтверждён только локальный запуск.
4. После показа ответственный снимает временную копию в согласованный срок. DNS предприятия и публикация из main для этого сценария не нужны.
