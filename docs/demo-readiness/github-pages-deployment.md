## Что получит зритель

Директор открывает ссылку в браузере, загружает публичный синтетический пример T06 и проводит расчёт. Измерения и результат находятся в памяти текущей вкладки. Установка программ на устройство зрителя не требуется. [Сценарий выступления](director-demo-script.md).

**Ожидаемый адрес проекта** — `https://volkov43-beep.github.io/vsz-positioning-calculator/`. После развёртывания взять фактический URL из окружения **github-pages** завершившегося запуска и проверить его по списку ниже. До этой проверки публичная ссылка для зрителей не подтверждена.

## Как собирается сайт

В режиме `pages` Vite использует базу `/vsz-positioning-calculator/` и одну HTML-точку входа. Поэтому ссылки на JS и CSS учитывают каталог репозитория. React-интерфейс и TypeScript-ядро попадают в один JS. У локальной сборки сохраняются относительные пути и отдельные точки входа оси и позиции. Скрипт однофайловой версии по-прежнему встраивает скрипт и стили в HTML. [Конфигурация Vite](../../vite.config.ts) · [Рекомендация Vite для Pages](https://vite.dev/guide/static-deploy.html#github-pages).

| Событие | Сборка и проверки | Публикация |
| --- | --- | --- |
| Pull request в main | Checkout, Node по .node-version, Python 3.12, npm ci, mpmath, typecheck, Vitest, однофайловая сборка, Pages-сборка | Загрузка артефакта и deploy пропущены |
| Push в main после слияния владельцем | Та же последовательность | При успехе загружается только dist/ и публикуется артефакт этого запуска |
| Run workflow вручную | Проверяется выбранная ревизия | Разрешена только для ветки main |

Задание build получает `contents: read`. У deploy есть только `pages: write` и `id-token: write`, оно зависит от успешного build и использует окружение `github-pages`. Личный токен не нужен. Публикации main выполняются последовательно. [Workflow](../../.github/workflows/deploy-pages.yml) · [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Официальные действия сверены с релизами на 20 ноября 2026 года и закреплены в workflow полными SHA. Версии — checkout 7.0.1, setup-node 7.1.0, setup-python 7.1.0, configure-pages 6.0.0, upload-pages-artifact 5.0.0 и deploy-pages 5.0.1.

## Первая публикация владельцем

1. Проверьте результат **build** и перечень файлов в [PR №11](https://github.com/volkov43-beep/vsz-positioning-calculator/pull/11). Нажмите **Ready for review**, затем **Merge pull request** и подтвердите слияние.
2. Откройте [Settings → Pages](https://github.com/volkov43-beep/vsz-positioning-calculator/settings/pages). В **Build and deployment → Source** выберите **GitHub Actions**. При повторном открытии страницы проверьте выбранный источник. Workflow уже есть в репозитории.
3. В [Actions → GitHub Pages](https://github.com/volkov43-beep/vsz-positioning-calculator/actions/workflows/deploy-pages.yml) откройте запуск для merge-коммита main. Если первый deploy успел завершиться ошибкой до выбора источника, после настройки запустите **Run workflow → Branch: main → Run workflow**.
4. После успеха build и deploy откройте URL окружения **github-pages**. Пройдите приёмку ниже, зафиксируйте SHA и фактический адрес. Рабочую ссылку можно передать директору после этой проверки.

## Воспроизведение и состав артефакта

На локальном стенде использованы Node.js 24.22.3, npm 11.19.1, Python 3.12.14 и mpmath 1.3.0. Из корня репозитория:

```sh
npm ci
python -m pip install -r tests/fixtures/v1/requirements.txt
npm run typecheck
npm test
npm run build
npm run build:demo
npm run build -- --mode pages
```

Обычная и однофайловая сборки воспроизводят все восемь [контрольных сумм DEMO-08](build-SHA256SUMS.txt). Команда в последней строке заново создаёт dist/ для сайта. ## Репетиция до публикации

Проверялся собранный dist/ по локальному HTTP в подкаталоге с тем же именем, что и на Pages. Браузер — Chrome 156 под Linux. Это отдельная репетиция до проверки публичного адреса.

| Проверка | Наблюдение |
| --- | --- |
| Первый экран и пути | HTML, JS и CSS вернули HTTP 200. После повторного открытия адреса и обновления страницы T06 снова рассчитался. Доступна crypto.subtle.digest. |
| T06 | 50 наблюдений, все 12 показателей, B = 4 мкм и B̄ = 0,8 мкм. После замены p03 ↑ №5 с 20 на 0 прежний отчёт отозван. Пересчёт дал 12 нулей, шесть рядов графика на нуле и отчёт редакции 2. Повторная загрузка восстановила 20. |
| Ручной ввод | В новом испытании вручную введены пять координат и 50 значений. Единственное −20 в p03 ↑ №5 дало B = 4 мкм и B̄ = −0,8 мкм. |
| Мобильный режим | Эмуляция ширины 390, 360 и 320 CSS px. На каждой ширине доступны десять полей одной позиции, правка, пересчёт, 12 итогов, график и демонстрационное предупреждение. Горизонтального переполнения всей страницы не обнаружено. Физический смартфон не проверялся. |
| Сеть и консоль | После ввода, обоих расчётов и просмотра отчёта в записях ресурсов страницы присутствовали только HTML, JS и CSS с того же узла. Измерений в URL и запросов к сторонним сервисам не обнаружено. Ошибок JavaScript приложения в консоли не было. |

## Приёмка по публичному HTTPS

Статус всех пунктов ниже — **ожидают первого успешного deploy**. Для приёмки использовать только синтетические значения.

- [ ] Зафиксировать SHA развёрнутого main, ссылку на запуск, фактический HTTPS-адрес, дату и браузер. Открыть адрес в новой вкладке, затем обновить страницу. Главная и все запрошенные JS/CSS возвращают 200 при первой загрузке, в консоли нет 404 и ошибок приложения. Проверить защищённый контекст и доступность Web Crypto.
- [ ] На первом экране видно предупреждение «Демонстрационный расчёт. Методика и численная политика проходят согласование. Не использовать для приёмки станков». Загрузить T06, проверить 50 из 50, получить 12 характеристик, B = 4 мкм и B̄ = 0,8 мкм. Открыть график и выбрать p03.
- [ ] Исправить p03 ↑ №5 с 20 на 0. До пересчёта отчёт сообщает об отсутствии актуального результата. После пересчёта проверить 12 нулей, совпадение рядов графика и отчёт новой редакции. Перезагрузить исходный T06 и проверить восстановление 20.
- [ ] Включить запись Network до загрузки страницы. Проверить загрузку T06, новый ручной ввод, расчёт, редактирование, пересчёт и отчёт. Просмотреть запросы, URL и переданные данные. Измерения должны оставаться в памяти вкладки.
- [ ] Повторить правку, пересчёт и просмотр графика на ширинах 390, 360 и 320 px. Убедиться, что доступны селектор позиции, десять измерений и предупреждение. Записать, использован ли физический телефон или эмуляция.

## Границы и сопровождение

Приложение работает в режиме `research-demo`, результат сохраняет `productionEligible: false`. Для политики `vsz-num-0.2` бюджеты представления входов ожидают утверждения. Измерения теряются при закрытии или обновлении вкладки. Хостинг может регистрировать обращения к статическим ресурсам, в том числе IP-адреса посетителей. Проверка сети приложения не охватывает браузерные расширения и настройки устройства. [Сведения GitHub Pages о сборе данных](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection).

**Обновление.** Внести правку через PR, дождаться зелёной проверки, объединить проверенный PR в main, сверить deploy и повторить T06 на фактическом HTTPS-адресе. При регрессии возвратить проверенное изменение отдельным PR.

**Снятие с публикации.** Сначала в **Actions → GitHub Pages → … → Disable workflow** остановить новые запуски и убедиться, что нет ожидающего или активного deploy. Затем в **Settings → Pages** открыть меню рядом с адресом сайта и нажать **Unpublish site**. Проверить, что прежний адрес перестал отдавать калькулятор. Для повторного размещения включить workflow и запустить его из main. [Инструкция GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/unpublishing-a-github-pages-site).
